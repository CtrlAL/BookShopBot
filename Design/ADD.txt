Твоя задача — развернуть в текущем проекте детерминированный каркас для Agent-Driven Development (ADD). Не пиши абстрактных объяснений: создай физические файлы и настрой конфигурацию, строго следуя требованиям ниже.

### 1. Файл правил агента: `.opencode/rules.md` (или `AGENT.md` в корне)
Создай файл инструкций, в котором зафиксируй:
* **TDD Invariant:** Запрещено редактировать код реализации в `src/` до создания падающего теста в `tests/`.
* **Scope Guard:** Запрещено изменять файлы вне явно заданной спецификации.
* **Non-Interactive Rule:** Запрещено задавать встречные вопросы во время автономных циклов.
* **Deterministic Verification:** Точные CLI-команды для линтинга, статической типизации и запуска тестов под текущий стек репозитория.
* **Circuit Breaker:** Ограничение на максимум 4 попытки самоисправления (self-healing), после чего агент обязан вернуть ненулевой код выхода и передать управление человеку.

### 2. Скрипт автономного цикла: `scripts/tdd_loop.py`
Напиши исполняемый Python-скрипт (Python 3.10+ без внешних pip-зависимостей), реализующий:
* Чтение спецификации задачи из файла `.tasks/current_task.md`.
* Цикл вызова CLI-агента (не более 5 итераций) с жесткими промптами.
* Пошаговую детерминированную валидацию после каждого шага агента:
  1. Сначала линтер / проверка типов (например, `tsc --noEmit` или `mypy`).
  2. Затем тесты (например, `pytest` или `npm test`).
* Передачу обрезанного стектрейса (последние 2000 символов) обратно в промпт следующей итерации при падении.
* Выход с кодом `0` только при 100% успехе всех проверок и с кодом `1` при превышении лимита попыток.

### 3. Защита от регрессий: Git Hooks (Pre-commit)
* Настрой конфигурацию хуков (через `Lefthook`, `Husky` или нативный `.git/hooks/pre-commit`).
* Хук обязан блокировать любой `git commit`, если локальные линтеры, проверки типов или затронутые тесты завершаются с ошибкой.

### 4. Директория задач: `.tasks/`
* Создай папку `.tasks/`.
* Создай файл `.tasks/template.md` со структурой:
  - `Context & Objective`: краткая цель.
  - `Interface Contract`: сигнатуры функций/типов.
  - `Acceptance Criteria`: чеклист требований.
  - `Affected Files`: строгий белый список файлов, доступных для редактирования.

Определи стек текущего проекта (Node.js/Python/Go) по имеющимся файлам манифестов (`package.json`, `pyproject.toml` и т.д.) и адаптируй все команды именно под него. Начни выполнение с генерации файлов.
