Пайплайн Agent-Driven Development (ADD) выстраивается вокруг автономных циклов агентов (генерация, валидация, самокоррекция) с контрольными точками человека (Human-in-the-Loop) на критических этапах.

1. **1. Декомпозиция и формулировка контракта:** Human-in-the-Loop: утверждение скоупа.
Человек или оркестратор формулирует высокоуровневую задачу. Агент-Архитектор декомпозирует её:

* Анализ кодовой базы (AST, семантический поиск, документация).
* Формирование технической спецификации и API-контрактов.
* Генерация плана выполнения (Checklist / Sub-tasks) с критериями приемки (Acceptance Criteria).


2. **2. TDD / Генерация тестового окружения:** Ограничение галлюцинаций до написания кода.
Агент-Тестировщик готовит окружение для строгой верификации:

* Написание интеграционных и модульных тестов на основе контракта.
* Фиксация граничных случаев (edge cases).
* Запуск тестов: на этом этапе они обязаны падать (**Red Phase**).


3. **3. Итеративная кодогенерация (Coder Agent):**
Агент-Разработчик берет подзадачи из плана и вносит изменения:

* Применение паттерна ReAct (Reasoning + Action) для навигации по репозиторию и редактирования файлов.
* Поддержка контекста: использование linter-логов и локального дерева зависимостей.
* Задача агента — добиться прохождения тестов при минимальном изменении структуры.


4. **4. Локальный цикл самодиагностики (Self-Healing Loop):** Автономный цикл без участия человека.
Код запускается в изолированной песочнице (Docker / Dev Container):

* Выполнение линтеров, статических анализаторов типов (`tsc`, `mypy`) и тестов.
* **Ветвление:** Если тесты упали, стек трейс и логи передаются агенту обратно в контекст для патча (максимум 3–5 итераций).
* Если тесты зеленые — переход к этапу ревью.


5. **5. Агентное рецензирование (Review & Security Agent):**
Независимый агент (с отдельным системным промптом) анализирует сгенерированный diff:

* Поиск уязвимостей (OWASP, утечки секретов, инъекции).
* Оценка архитектурного долга, избыточности кода и соответствия code style.
* Оценка покрытия тестами (Code Coverage).


6. **6. Human Validation & PR Merging:** Human-in-the-Loop: финальный гейткипер.
* Формирование Pull Request с автосгенерированным changelog и ссылками на спецификацию.
* Быстрое ревью инженером: проверка бизнес-логики и архитектурных компромиссов.
* Слияние в ветку и запуск основного CI/CD.


---

**Ключевые механизмы устойчивости пайплайна:**

* **Контекстные границы:** Агенту подается не весь репозиторий, а только срезы (сжатые сигнатуры типов, релевантные модули через RAG/AST).
* **Deterministic Guardrails:** Проверку компиляции и тестов выполняет не LLM, а локальный рантайм CLI (bash tool).
* **Hard Limits:** Обязательный лимит на число итераций в цикле самоисправления (circuit breaker), чтобы агент не уходил в бесконечный рефакторинг при неверных тестах.
