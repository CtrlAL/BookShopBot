# Agent Rules — BookShopBot (ADD Framework)

## 1. TDD Invariant

Запрещено редактировать файлы реализации (`*.cs` в `src/`, `BookShop/`, `ChatFSM/`, `TelegramBot/`) до создания **падающего** теста в `tests/`. Порядок действий:
1. Создать/обновить тест-кейс, который воспроизводит требуемое поведение.
2. Убедиться, что тест падает (`dotnet test` завершается с ненулевым кодом).
3. Только после этого вносить изменения в код реализации.
4. Убедиться, что тест проходит.

Исключение: автономные фиксы комментариев, документации, `.editorconfig` и `.gitignore` не требуют тестов.

## 2. Scope Guard

Запрещено изменять файлы вне белого списка, указанного в текущей задаче (`.tasks/current_task.md` секция `Affected Files`). Если белый список пуст — разрешено изменять только файлы, непосредственно связанные с задачей. Любое отклонение требует явного указания человека.

Запрещено:
- Добавлять новые NuGet-пакеты без явного указания в спецификации.
- Изменять `*.sln` файлы,除非 задача явно требует этого.
- Рефакторить код, не связанный с текущей задачей.

## 3. Non-Interactive Rule

Во время автономных циклов (вызов `scripts/tdd_loop.py` или агентных пайплайнов) запрещено:
- Задавать встречные вопросы пользователю.
- Прерывать выполнение для уточнений.
- Останавливаться на промежуточных шагах без ошибки.

Все неопределённости должны быть разрешены **до** запуска автономного цикла. Если агент не может продолжить — прервать цикл с ненулевым кодом выхода.

## 4. Deterministic Verification

Точные CLI-команды для текущего стека (C# / .NET 8+):

### Линтер / форматирование
```bash
dotnet format BookShop/BookShop.sln --verify-no-changes --verbosity diagnostic
```

### Статический анализ (включает проверку типов)
```bash
dotnet build BookShop/BookShop.sln --no-restore -p:WarningsAsErrors=CS*
```

### Тесты
```bash
dotnet test BookShop/BookShop.sln --no-build --verbosity normal
```

### Полная последовательность (порядок严格执行!)
```bash
dotnet build BookShop/BookShop.sln --no-restore -p:WarningsAsErrors=CS* && \
dotnet test BookShop/BookShop.sln --no-build --verbosity normal
```

> **Важно:**
> 1. `dotnet format --verify-no-changes` не заменяет `dotnet build`. Форматирование проверяет стиль, но не компиляцию. Всегда запускайте обе команды.
> 2. Вместо общего `-warnaserror` используется `-p:WarningsAsErrors=CS*` — повышает до ошибок **только C#-компиляторные предупреждения (CS)**. Два известных предсуществующих предупреждения (NU1902 OpenTelemetry, Grpc.Net.ClientFactory 2.63) сознательно не блокируют коммиты; они отмечены в `roadmap.md` как известные — исправить (upgrade),
>    но не задерживать разработку.
> 3. `dotnet build` без `--no-restore` выполняет restore и НЕ детерминирован по времени — в автономных циклах использовать только с `--no-restore`. Первичный restore — через отдельный `dotnet restore BookShop/BookShop.sln`.

## 5. Circuit Breaker

Ограничение на максимум **4 попытки самоисправления** (self-healing).

### Логика:
1. Агент выполняет шаг → запускает `dotnet build` → `dotnet test`.
2. При ошибке: анализирует стектрейс, исправляет код, повторяет.
3. Счётчик попыток увеличивается на 1 после каждой итерации修复失败.
4. При достижении лимита (4 попытки):
   - Агент **обязан** вернуть ненулевой код выхода (`exit 1`).
   - Вывести краткую сводку: что было сделано, какая ошибка осталась.
   - Передать управление человеку.

### Формат отчёта при Circuit Breaker:
```
[CIRCUIT BREAKER] After 4 attempts, unable to resolve:
- Last error: <сообщение об ошибке>
- Attempted fixes: <список изменений>
- Files touched: <список файлов>
- Action required: manual intervention
```
